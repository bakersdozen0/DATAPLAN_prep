# DATAPLAN Prep: Unified Master Pipeline

This repository contains the R-based data processing pipeline for standardizing, validating, and formatting raw tree breeding data exported from the CEDD prior to upload to Dataplan. 

It takes raw ASCII exports, merges them with design files and spatial matrices, applies validation rules (outlier detection, temporal shrinkage checks, spatial coordinate mapping), and outputs clean, wide-format datasets, graphical summaries, and `.xml` files.

## ⚠️ Important Setup Instructions (Read First)

This project uses a **hybrid file architecture**:
1. **The Code:** Lives locally on your `C:` drive (managed via this GitHub repository).
2. **The Data:** Lives externally on the shared network drive (`Z:`) or synced Teams/SharePoint folders.

**Do NOT copy raw data (`.csv`, `.xlsx`, `.txt`) into this local repository.** To run these scripts, you must define the `BASE_DIR` and `TRIAL_SERIES` path variables at the top of the scripts to point to your data location.

## Core Scripts

### 1. Traversal Diagnostic & Orientation Tool (`Data_orientation_corrections.R`)
Before running the master pipeline for multi-tree plots, use this tool to detect and solve "The Scrambled Egg" problem (where assessors walked a different path through a plot than the database expects).
* **16-Way Brute Force:** Simulates all 16 possible physical traversal paths (Starting corners, Horizontal/Vertical, Typewriter/Snake) and finds the one that maximizes biological correlation against a trusted anchor.
* **Temporal Chaining:** Supports iterative cleaning (e.g., using a corrected Age 6 trait as a "stepping stone" anchor to fix Age 3 data).
* **Zombie Filter:** A time-aware mortality check that prevents false-positive corrections by invalidating any traversal path that creates biological impossibilities (e.g., a tree dead at age 3 appearing alive at age 15).
* **Output:** Generates a `TRAVERSAL_HELPER_MASTER.csv`—a "recipe book" of surgical fixes that the Master Script reads automatically.

### 2. The Master Script (`DP_batch_process_Master.R`)
The core execution engine, refactored to handle complex corrections and standardizations:
* **Surgical ID Re-alignment:** Automatically detects the presence of a `TRAVERSAL_HELPER_MASTER.csv`. It "un-scrambles" the Tree IDs for specific plots and traits, stamping the fix and the anchor used into the final validation record.
* **Global Zero-Padding:** Automatically enforces leading zeros on all assessment ages (e.g., `Ht_3` becomes `Ht_03`). This ensures trait names match flawlessly between raw ASCII data, additional data (AD) files, and diagnostic helper rules.
* **Dynamic Species Handling:** Reads the `species` code from raw data to build correct genetic family names and control prefixes (e.g., `ss_` vs `sp_`).
* **Format Agnostic:** Seamlessly accepts `.csv` and `.xlsx` for raw data/AD files, and `.txt` or `.xlsx` for design files.

### 3. Pedigree Generation (`Pedigree.R`)
* Generates import files (`Groups`, `Genotypes`, `Families`) by cross-referencing field trial data against the founder database and existing Dataplan records.

### 4. Reading Field Data Sheets (`read_BrSt_sheets.R`)
* A parser for extracting Branch and Straightness (Br/St) assessment data from unformatted Kintyre field layout sheets into tidy formats.

# ⚙️ Workflow: The "Temporal Chain" Strategy

To ensure the highest data integrity in multi-tree trials, the following workflow is recommended:

1.  **Baseline Run:** Run the Master Script on raw data to produce an initial `_Full_Data_With_Flags.csv`.
2.  **Anchor Check:** Use the Diagnostic Tool to verify a late-age trait (e.g., `Dm_15`) against another stable trait (e.g., `Ht_13`). If they correlate tightly, `Dm_15` is your "Absolute Anchor."
3.  **Middle-Age Fix:** Run the Diagnostic Tool comparing a suspect middle-age trait (e.g., `Ht_06`) against the `Dm_15` anchor. Save the results to the Master Helper.
4.  **Early-Age Fix (The Chain):** Toggle `USE_CORRECTED_DATA <- TRUE` in the Diagnostic Tool. Run a diagnostic for the early-age trait (e.g., `Ht_03`) using the *corrected* `Ht_06` as the anchor.
5.  **Final pass:** Run the Master Script on the raw data folder. It will apply the entire chain of fixes simultaneously to produce the final dataset.

# 📂 Folder Structure & Requirements

### 📁 Expected Trial Folder Input
The script dynamically crawls the `TRIAL_SERIES` folder for:
1. **`*_ASCII.csv/xlsx`** *(Required)*: The raw measurement export.
2. **`*_DF.xlsx/txt`** *(Optional)*: The design file containing Crosses and Blocks.
3. **`*_Matrix.csv`** *(Optional)*: The physical spatial layout of the trial.
4. **`*_AD_<age>.csv/xlsx`** *(Optional)*: Additional Data (e.g., Resi) to be merged.
5. **`TRAVERSAL_HELPER_MASTER.csv`** *(Optional)*: The orientation "recipe book" generated by the Diagnostic Tool.

### 📊 Pipeline Outputs
* `*_Full_Data_With_Flags_Corrected.csv`: Master wide-format dataset with all spatial, pedigree, and corrected measurement data.
* `*_graphs_Corrected.pdf`: Comprehensive diagnostic report featuring **Spearman Rho** coefficients on all correlation plots to verify the success of ID re-alignment.
* `*_Stats_Corrected.csv`: Summary statistics (N, Mean, CV%, etc.) for all valid traits.
* `*_Traits.xml`: Standardized XML trait definitions for Dataplan upload.

### 🛑 Validation Flags (`Reject_Flag = 1`)
* **Extreme Outliers:** Values exceeding Mean ± 4 SD.
* **Temporal Shrinkage:** Measurements (Ht/Dm) strictly smaller than the previous age.
* **ID Re-alignment:** If a tree was moved by the diagnostic logic, the `Validation_record` will state: *"ID Realigned from [Path] (Anchored to [Trait])"*.
